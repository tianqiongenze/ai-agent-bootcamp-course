# 教学方案"小白化"改造规范（供批量修订与 PPT 重建使用）

> 目标：让专科大一、大二学生"看懂、学会"。本规范与 `scripts/build_ppt.py`（v2 渲染器）配套：
> 新增的 md 内容会被自动渲染成新页型，改完方案后运行 `python3 scripts/build_ppt.py` 即可重建全部 PPT。

## 一、新增章节：本讲术语小白卡

**位置**：`## 一、学习情境基本信息` 之后、`## 二、任务描述` 之前，新增：

```markdown
## 〇、本讲术语小白卡（先看懂再开工）

| 术语 | 人话解释 | 生活化类比 |
|---|---|---|
| 数仓分层 | 把数据像仓库一样分区存放：原料区(ODS)→粗加工区(DWD)→半成品区(DWS)→成品区(ADS) | 厨房：冰箱、洗菜池、备菜台、出餐口 |
| Schema Linking | 系统先猜你的问题要用哪几张表哪几列，只把这些塞给 AI，省 token 又防串台 | 图书管理员先按书名定位书架，不把整个馆搬给你 |
```

**书写要求**：
1. 每讲 5–8 个术语（本讲真正用到的，宁缺毋滥）；
2. "人话解释"≤40 字、零嵌套术语（解释里不得再出现没解释过的黑话）；
3. "生活化类比"必须是学生日常经验（食堂/快递/图书馆/游戏/微信群…），≤30 字；
4. PPT 渲染为两列卡片网格，每卡显示术语+人话解释（含类比），超 8 个自动分页。

## 二、新增 flow 块：关键流程图形化

每讲在"教学过程设计"或"教学重点与难点"最合适的位置，把最核心的流程用 flow 块书写（PPT 自动渲染为人字形箭头流程图）：

````markdown
```flow
问句 → ①意图理解 → ②Schema Linking → ③LLM生成 → ④自校验 → ⑤沙箱执行 → 结果
```
````

**书写要求**：
1. 一行一个流程；每行 3–8 个节点，节点文字 ≤10 字；
2. 节点编号用 ①②③ 便于口述；失败出口写进"教学难点"文字里，不塞进 flow；
3. 每讲 1–2 个 flow（最重要的一条主链路 + 至多一条分支/对照链路）。

## 三、既有内容的"小白化"改写原则（就地优化，不推翻结构）

1. **难点拆台阶**：每个教学难点的"突破策略"必须含"三步台阶"：台阶1-生活类比建立直觉 → 台阶2-看一次真实演示/日志 → 台阶3-学生动手复现。
2. **首次出现的术语**在正文中首次出现时用"术语（人话一句话）"格式就地解释。
3. **命令与代码**：每段命令上方加一行"这步在干什么"；预期输出旁加"怎么判断对了"。
4. **数字都有锚**：420ms、56s、91.7%、140RPS 等指标首次出现必须配"这相当于什么"的参照物。
5. **不动**：学时数、六步法时间轴、考核权重、布鲁姆标注口径（与课程标准强一致，改则四处失配）。

## 四、批量执行方式

- 按讲次分组（L01–L04 / L05–L08 / L09–L12 / L13–L16）四个批次并行修订；
- 每讲修订完成后跑 `python3 scripts/build_ppt.py Lxx` 单讲重建验证；
- 全部完成后重跑 `python3 scripts/build_docs.py` 同步 Word/PDF 导出。
