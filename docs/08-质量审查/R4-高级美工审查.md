## 二、致命发现（先于一切评分）

### P0-1 自动分页的单位换算 Bug —— 内容被渲染到幻灯片外（学生看不见）

`build_ppt.py` `render_blocks()`（L329–338）：

```python
h = est_block_height(block, CONTENT_W / 914400, size)   # 返回单位是「磅 pt」
if y + h > CONTENT_BOTTOM and ...:                       # y / CONTENT_BOTTOM 是「EMU」
```

`est_block_height` 返回**磅**，而 `y`、`CONTENT_BOTTOM` 是 **EMU**（1pt = 12700 EMU）。`y + h` 中 h 的贡献约为零，溢出判断退化为"块顶 y 是否已越过 6.95in"。后果实测：

- **39 个形状越过页脚线（7.08in），其中 24 个深入 >0.3in**；
- **6 页内容底边到达 9.2–9.56in，而幻灯片物理高度只有 7.5in** —— 超出部分投影时**完全不可见**，且无任何截断提示：

| 页面 | 内容底边 | 越界深度 | 该页字数 |
|---|---|---|---|
| L05 p8 | 9.56in | 2.48in（出画） | 1015 字 |
| L02 p14 | 9.54in | 2.46in（出画） | 1120 字 |
| L11 p12 | 9.54in | 2.46in（出画） | 1246 字 |
| L05 p13 | 9.53in | 2.45in（出画） | 1585 字 |
| L10 p13 | 9.22in | 2.14in（出画） | 1291 字 |
| L06 p11 | 9.22in | 2.14in（出画） | 1500 字 |

- 连带效应：`cursor_state` 续页逻辑形同虚设（只有块顶越过底线才翻页），导致"实施"页普遍 1200–1600 字堆在一页 —— 密度灾难的根源之一。
- 非游标路径的 `continue`（静默丢弃块）同样被该 Bug 掩护：当前内容几乎不触发，但一旦修复单位 Bug，各非游标分区（基本信息/任务描述/学习目标/重点难点/教学准备/评价设计/课后费曼）将开始大面积触发静默丢块 —— **修复时必须同时把 `continue` 改为"续页或显式截断提示"**。

**修复方案（一行级）**：`h_emu = Emu(int(est_block_height(...) * 12700))` 后再参与比较；同时在 `est_block_height` 各分支核对返回单位注释。

### P0-2 表格/列表高度估算与 PowerPoint 实际渲染不一致的风险

`add_table` 设定的高度是"建议值"，PowerPoint 会按换行后实际行数自动加高。当前 113 个表格页尚未爆发，但任何单元格换行超出估算（尤其 10–11pt 长句）都会把表格下缘推进页脚。修复 P0-1 后应把表格高度估算系数从 1.5 提到 1.7，并给表格预留 `y + est + 0.2in ≤ CONTENT_BOTTOM` 的安全余量。

## 四、典型问题核查结论

1. **表格 16 行截断**：当前 16 讲中**未触发**（实测最大表格 9 行）——`render_table` 的 max_rows=16 与提示逻辑属"潜伏代码"，暂无观感问题，但 L04 六步总表源 md 有 40+ 行，建议改为"分栏分页渲染"而不是等它触发。
2. **代码 14 行截断**：**已触发 13 处**（另有 16 个代码块恰好 14 行=贴帽），提示语"详见教学方案原文"对学生无意义（课上没人开 md）。L04 p13 一块代码被砍 25 行、L05 p13 砍 14 行 —— 关键操作步骤在投影上缺失。另有每行 110 字符硬截（`ln[:110]`）无省略号，长命令静默断头。
3. **续页"（续N）"体验**：45 个续页（L09"实施"拖到续4）。续页标题只重复步骤名，无"本页讲什么"小导航；且因 P0-1，续页自身也常超装（续页反而出现在最高密度 Top12 中）。
4. **导航条遮挡**：六步条位于 1.12–1.42in，六步页正文从 1.56in 起 —— 无遮挡，但净距仅 0.14in，视觉偏挤；非六步页不显示导航条，学生失去全课位置感（导航只在 1/3 的页面出现，设计价值打折）。
5. **纯文字墙**：99 页（30%）无任何图形/表格/代码，集中在 p4–p7（任务描述/学习目标/重点/难点）＋首尾页。开场 30 分钟全是文字页，对大一/大二学生是最不友好的注意力区间。
6. **术语密度**：NL2SQL/RAG/HPA/ADR/血缘/DAG 等术语首讲即高密度出现，全套 16 讲**无一处术语卡片/小白卡页型**，无从缓解。

## 六、可直接实施的设计升级方案（面向专科大一/大二学生）

以下每项均给出 `build_ppt.py` 落地点，按投入产出排序。

### 1. 修复布局引擎（P0-1/P0-2，半天）
- `render_blocks()`：统一单位 —— `h_emu = Emu(int(est_block_height(...) * 12700))`；恢复真正自动分页。
- `continue` 改为：非游标分区也走 cursor 续页；单块（大表/大码）超页高时启用"分片渲染"（表格按行分片、代码按行分片），替代"另有 N 行"提示。
- 表格高度系数 1.5→1.7，代码行高 1.35→1.45，预留 0.2in 底部安全带。

### 2. 字号红线制度（P0-2/P1-3，1 小时）
在脚本头部建立字号标尺并全库替换硬编码：
```
SIZE_TITLE=26  SIZE_H3=18  SIZE_BODY=16  SIZE_BODY_MIN=14
SIZE_TABLE=13（表格正文，≈正文-2）  SIZE_CODE=13  SIZE_CAPTION=11  SIZE_FOOTER=10
```
- `render_table`：`body_size = max(size-2, SIZE_TABLE)`，表格页统一按 `size=16` 调用 → 表格正文 ≥13pt；行数>8 的表自动分片到续页。
- `render_code`：`max(size-1, 13)`；行截断提示改为"→ 完整代码见任务工单/代码仓库 xxx.py"。
- 教学准备/六步总表/评价设计三处 `size=13` → 14；页脚 9→10pt，并传入 total 显示"07 / 22"。

### 3. 单页字数红线 ＋ "一页一事"（P1-1，配合方案 1）
- `render_blocks` 修复后，加硬性约束：单页渲染字数（est 累计）> 320 字即强制续页，续页标题带内容摘要（取本页首个 h3/首句 8 字），如"六步法 · 实施（续2）· 任务定义 JSON 字段"。
- 目标页/任务页等长段落改"要点卡"：`render_para` 检测 >90 字段落时自动拆为 2–3 张横向卡片（圆角矩形 + 16pt 要点），每卡 ≤45 字。

### 4. 新页型三件套（P1-4/P1-5，核心增量，2 天）
- **术语小白卡页型** `render_term_card(slide, term, en, plain, analogy)`：半页 2×2 网格，每卡：术语 20pt 橙色 ＋ 一句大白话 15pt ＋ 生活化类比 13pt 斜体。资讯步骤首个 h3 前自动插入。实现：`parse_lesson` 增加 terms 提取（扫描 md 中 `**术语（English）**` 模式），`build_lesson_ppt` 在资讯分区前渲染。
- **流程图解页型** `render_flow(slide, steps, mode)`：用 MSO_SHAPE.CHEVRON/ROUNDED_RECTANGLE ＋ 箭头连接符画横向流程（六步法总览、NL2SQL 五步链路、RAG 检索链路、ETL 五步、安全四层）。每讲至少把"六步法过程总表"页改为流程图＋每步学时徽标；`render_flow` 读取总表数据自动生成。
- **图解卡片页型**：学习目标页改为布鲁姆金字塔（6 层梯形，MSO_SHAPE.TRAPEZOID 堆叠，层级色由 C_ACCENT 渐进到 C_HIGHLIGHT）；重点/难点页改为左右双卡（重点=青蓝边框卡，难点=橙边框卡＋"突破策略"角标）。

### 5. 色彩语义规范（30 分钟）
在主题区追加并全库贯彻：
```
C_INFO=C_ACCENT（定义/概念）  C_WARN=C_HIGHLIGHT（难点/易错/截断警示）
C_OK=RGB(0x2E,0x8B,0x57)（检查/达标项）  C_DANGER=RGB(0xC0,0x39,0x2B)（红线/禁止项）
```
- 重点页标题条用 C_OK 不合适 → 重点=C_ACCENT、难点=C_WARN、安全红线=C_DANGER；"诚实清单/HSA"相关行用 C_DANGER 左边条。
- 议程数字块、导航高亮的白字改压 C_PRIMARY（对比度 12:1），或青蓝加深为 #1D6FBF。

### 6. 导航条全页化 ＋ 进度感知（1 小时）
- 所有内容页显示六步条（非六步页整条降透明度/灰态），学生随时知道"现在在哪"；实现：`new_content_page` 增加 `phase` 参数，非步骤页传 `step_idx=-1` 走灰态分支。
- 续页标题格式改为"实施 3/5 ·（续2）"，由 cursor 循环传入 part/total（预估总续页数：`ceil(总高/可用高)`）。

### 7. 截断体验改造（1 小时）
- "详见教学方案原文"→ 指向学生可达载体："完整 40 行见任务工单 T-xx / 仓库 docs/xxx"；至少把提示字号 10→12pt、颜色 C_WARN。
- 代码 110 字符截断改为自动折行（`textwrap` 按 96 列折行，续行缩进 2 空格），并在折行处加"↪"。

### 8. 教学方案源头减负（与内容侧协同，长期）
- 与教学方案评审（R2/R3）联动设定"PPT 视图预算"：每个 h3 块 ≤180 字；表格 ≤8 行/页；代码 ≤12 行/块。可在 `parse_blocks` 后加"超预算告警"打印，倒逼 md 瘦身，而不是让 PPT 硬塞。

## 七、结论

管线的"单一事实源＋模板一致性"是优秀底座（一致性 8/10），但当前输出对课堂投影不可用：**1 个单位 Bug 让自动分页失效**，叠加信息量超载，造成 82% 页面超字数红线、23 页超千字、6 页内容出画不可见、113 个表格页正文 10–11pt。先修 P0（半天～1 天），再落地方案 1–5（约一周），可读性可从"不达标"提升到"专科课堂友好"；方案 4 的三个新页型（术语小白卡/流程图解/布鲁姆金字塔）是把课件从"文档墙"变成"教学媒体"的关键增量。
