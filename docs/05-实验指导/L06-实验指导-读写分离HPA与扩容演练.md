## 一、实验目标

1. 【应用】扩容一个 worker 副本并验证 HPA/PDB 行为（对应课程标准 LF2 企业任务）。
2. 【分析】剖析 dap-v2 读写分离实现（写 DSN / 读 DSN 双连接池）。
3. 【评价】复述"容量诚实"口径：为什么 100 万并发不能在本集群真压，外推公式怎么算（ADR-004）。

## 二、环境与准备

- 前置：L05 五件套全绿（未达标者先补 M1 缺项）。
- 材料：gateway 数据访问层源码中双 DSN 初始化片段（教师标注范围）；HPA/PDB 清单。

## 三、实验步骤

### 步骤 1：读写分离代码剖析（30′）

通读指定代码段，回答：

1. 写连接与读连接的 DSN 差异是什么？指向哪个实例？
2. 什么情况下读请求会 fallback 到写库？（主从延迟容忍策略）
3. 如果把一个聚合统计误路由到写库，会造成什么连锁问题？

✓ 验证点：剖析笔记三问齐全，第 3 问要有传导链（写放大→锁竞争→在线交易受影响）。

### 步骤 2：扩容演练（40′）

```bash
kubectl -n dap-course-XX scale deploy/worker --replicas=4
kubectl -n dap-course-XX get hpa worker -w        # 观测期望副本 vs 当前副本
kubectl -n dap-course-XX describe pdb worker      # PDB 允许的中断数变化
```

模拟压力（教师发放的轻量压测脚本，目标 RPS 低于集群拐点），记录：

|---|---|---|---|
| T0（扩容前） |  |  |  |
| T+2′ |  |  |  |
| T+5′ |  |  |  |

✓ 验证点：HPA 触发记录 ≥2 次；PDB 行为解释写入报告。

### 步骤 3：容量外推练习（15′）

按 ADR-004：以本次实测单副本吞吐为基准，线性外推"百万用户"所需副本数，并写出**该外推成立的 2 个前提**（线性段内、依赖不成为瓶颈）。

### 步骤 4：M1 自检（5′）

对照《里程碑验收单 M1》五项逐条自查，缺项列入诚实清单。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| HPA 不动作 | 指标源未装/阈值区间未跨过；先看 `describe hpa` 的 Metrics |
| 扩容后 Pod 一直 Pending | 资源配额/节点资源不足——正好是容量诚实的活教材，记录之 |
| 读延迟上升 | 主从延迟窗口内读到旧数据；解释"读己之写"场景应走写库 |
