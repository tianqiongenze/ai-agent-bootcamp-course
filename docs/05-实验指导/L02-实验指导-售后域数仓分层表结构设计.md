## 一、实验目标

1. 【理解】解读 105.9 万订单零售数仓的 ER 关系与现有分层（ODS→DWD/DIM→DWS→ADS）。
2. 【应用】为"售后域"（工单/退换货/维修）设计 ODS 与 DWD 层表结构并说明分层理由。
3. 【评价】能判断一张明细表"该不该下沉到 DWS"并给出依据。

## 二、环境与准备

- 只读连接样例：`mysql -h 10.167.2.176 -P 4000 -u course_ro -p --ssl-mode=VERIFY_IDENTITY`
- 数据字典：课程仓库 `docs/07-项目资源/` 下 SAD 附录中的零售数仓表清单。
- 约束：本实验只提交 **DDL 草案（.sql 文件）**，不执行任何 DDL——生产数仓结构变更走企业审批，课堂上只做设计评审。

## 三、实验步骤

### 步骤 1：解剖现有数仓（30′）

```sql
-- 只读探查
SHOW DATABASES;
USE retail_dw;
SHOW TABLES;
SELECT COUNT(*) FROM dwd_order;           -- 预期 ≈ 1,059,000（以实际为准）
DESC dwd_order; DESC dim_store; DESC dws_store_day;
```

✓ 验证点：完成《数据集解剖表》（每张核心表记录：粒度/主键/分区键/上游层来源）。

### 步骤 2：售后域分层设计（50′）

1. 面向"售后工单"设计 4 张表：`ods_cs_ticket`（接入）、`dwd_cs_ticket_di`（明细）、`dws_cs_ticket_1d`（日汇总）、`ads_cs_sla_day`（SLA 看板）。
2. 每张表标注：粒度、主键、分区策略、刷新方式（全量/增量）、保留策略。
3. 回答两个设计问答（写入 PR 描述）：
   - "为什么 `dwd_cs_ticket_di` 不直接给业务方查？"
   - "如果运营要'本月退换货 TOP10 门店'，该从哪层取？为什么？"

✓ 验证点：DDL 草案通过组间互查（分层不越级引用、粒度声明清晰）。

### 步骤 3：提交 PR（20′）

- 文件：`design/L02-cs-domain-ddl.sql` + `design/L02-分层说明.md`
- PR 描述须含：分层结构图（文本图即可）+ 两个设计问答 + 诚实清单。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 把状态字段设计进 DWS 汇总 | 汇总层丢失明细状态语义；状态类需求回 DWD 取 |
| 分区键选了高频更新列 | 分区裁剪失效；分区键选日期类低更新列 |
| ODS 直接被 ADS 引用 | 越层引用破坏分层治理；链路必须逐层 |
