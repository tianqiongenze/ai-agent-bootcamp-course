## 一、实验目标

1. 【应用】用 GitOps 方式部署 TiDB/CRDB/Milvus/Pulsar/Redis 五件套并全部 Ready。
2. 【应用】执行 `make diff` 漂移检测并解读输出。
3. 【记忆/理解】能对每个中间件说出"它解决什么问题"（学生讲堂②素材）。

## 二、环境与准备

- GitOps 目录：课程仓库 `deploy/k8s/`（声明式清单为单一事实源）。
- 分工建议：1 人执行 apply、1 人盯 Pod 状态、1 人记录《五件套分工表》、1 人准备讲堂讲稿。
- 资源提醒：课程命名空间资源配额有限，副本数按清单默认值，**不得擅自扩副本**（扩容演练是 L06 的事）。

### 步骤 2：GitOps 部署（60′）

```bash
cd deploy/k8s
kubectl -n dap-course-XX apply -k overlays/course/   # kustomize 分层
kubectl -n dap-course-XX get pods -w                 # 全部 Running/Ready 为止
```

✓ 验证点：五件套 Pod 状态截图（一次截全，含 Ready 列）。

```bash
make diff     # GitOps 漂移检测
```

✓ 验证点：`make diff` 输出截图；有差异时逐条解释（改了什么/是否回滚）。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| Milvus Pending | 资源配额不足或 PVC 未绑；`describe pod` 看事件，报告教师调额 |
| Pulsar broker 起不来 | 依赖 zookeeper 就绪顺序；按清单 initContainer 等待逻辑排查 |
| diff 出现"计划外漂移" | 有人手动 kubectl edit 过——GitOps 纪律：改清单再 apply，不碰线上 |
| 灌数后行数对不上 | seed 未灌完/重复灌；记录误差并诚实写入清单，不圆数字 |
