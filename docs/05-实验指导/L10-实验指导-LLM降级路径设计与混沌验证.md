## 一、实验目标

1. 【分析】验证降级矩阵：主模型→备模型→确定性模板（DPC）的触发条件与行为差异。
2. 【评价】验证三级缓存（L1 进程内/L2 Redis/L3 语义缓存）命中链与降级的组合行为。
3. 【素养】体会"降级不是失败，是把失败变成可预期"（DPC 铁律）。

## 二、环境与准备

- 注入手段（教师授权）：断 Redis 连接、修改主模型端点为无效地址（均在课程命名空间内）。
- 安全边界：**只允许对课程命名空间注入**；对生产命名空间的任何操作 = 安全红线（EVAL-02 §三）。
- 计分表准备：记录每次调用的 model 标记、时延、是否命中缓存。

## 三、实验步骤

### 步骤 1：基线与缓存命中链（30′）

同一问句连续调用 4 次，记录：

| 调用次 | L1 | L2 | L3 | 实际路径 | 时延 |
|---|---|---|---|---|---|
| 1 | miss | miss | miss | 全链路 |  |
| 2 |  |  |  |  |  |
| 3 |  |  |  |  |  |
| 4 |  |  |  |  |  |

✓ 验证点：命中层级随调用次数变化可解释（先 L1 后 L2/L3）。

### 步骤 2：主模型故障注入（30′）

1. 将主模型端点置为无效 → 发起查询。
2. 记录：是否自动切换备模型？备模型响应质量差异（同一问句对比两次 SQL）。
3. 再把备模型也置无效 → 应落 DPC 确定性模板（返回受控话术/拒绝而非瞎编）。

✓ 验证点：三级降级各 1 次日志截图；恢复主模型后验证回落正常。

### 步骤 3：Redis 故障注入（30′）

1. 断 Redis → 观察缓存层降级行为（穿透到 LLM 还是快速失败？）。
2. 恢复 Redis → 验证缓存重新生效。
3. 对照 dap-v2 生产约定：这类混沌场景在上线前必须验证（发布检查单之一）。

### 步骤 4：成本对照表（10′）

| 路径 | 时延 | 估算相对成本 | 适用场景 |
|---|---|---|---|
| FAQ 直答 | ~420ms | ≈0（零推理） | 精确命中 |
| LLM 全链路 | ~56s | 高 | 新问句 |
| 语义缓存命中 | <1s | 低 | 高频相似问 |

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 注入后一直挂起不降级 | 超时配置缺失；检查重试/超时参数（生产用 `curl -m` 的经验同理） |
| 恢复后仍走备模型 | 熔断器半开窗口未过；等窗口或重启验证 |
| 降级到 DPC 返回"暂不支持"被判失败 | 判断标准错了——受控拒绝优于幻觉 SQL |
