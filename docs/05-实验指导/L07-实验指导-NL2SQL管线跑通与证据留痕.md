## 一、实验目标

1. 【应用】通过控制台/网关完成 3 条问句的端到端查询并留证据。
2. 【理解】对照五步管线日志，指出每一步的中间产物与耗时。
3. 【应用】刻意构造 1 条会走"模板降级"的问句，记录降级路径（model 标记）。

## 二、环境与准备

- 访问方式：控制台 `https://console.dap-v2.local`（课程账号 course-student-XX）。
- 认证提醒：直接调网关 REST/GraphQL 时必须带内部认证头 `x-internal-token`（tools 服务有 401 拦截）。
- 日志查看：教师发放只读日志检索入口（Loki/文件均可），本实验核心是**看轨迹**。

## 三、实验步骤

### 步骤 1：三条问句跑通（50′）

问句建议（自选 3 条，难度递进）：

| # | 难度 | 示例问句 | 预期观察 |
|---|---|---|---|
| 1 | 易 | "上个月全国总销售额是多少" | 命中现成口径，SQL 简单 |
| 2 | 中 | "华东区各门店上月 GMV 排名前 5" | Schema Linking 收敛到订单+门店表 |
| 3 | 难 | "环比增长最快的 3 个品类" | 涉及两期聚合，观察自校验是否纠正列名幻觉 |

每条记录（证据包模板）：

```
问句：<原文>
生成 SQL：<从控制台复制>
返回行数：<n> 行
耗时分布：SchemaLinking __ms / 检索 __ms / LLM __ms / 自校验 __ms / 沙箱 __ms
model 标记：<llm / template / faq-hit>
截图编号：<S-07-XX>
```

✓ 验证点：行数与 SQL 结果在 TiDB 手工复核一致（截图 DBeaver/mysql 客户端比对）。

### 步骤 2：降级路径实验（30′）

1. 故意输入一条知识库完全没有的新域问句（如"售后工单处理时长"——注意此时知识索引还没建）。
2. 观察降级矩阵行为：主模型→备模型→**确定性模板（DPC）**的触发顺序，记录每级 model 标记与响应差异。
3. 结论题：为什么 DPC 模板返回"暂不支持"也算**正确的失败**？从护栏与诚实文化角度写 3 句话。

✓ 验证点：降级链路日志截图 + 结论段。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 调用返回 401 | 少内部认证头；检查请求封装 |
| 查询超时 | 问句命中全表扫描型 SQL；看沙箱是否加了 LIMIT，记录后换低难度问句 |
| SQL 结果与控制台不一致 | 比对时间窗口（时区/日期边界）；以沙箱执行结果为准并记录差异 |
| macOS 本机调 SSE 流式接口卡死 | 本机无 `timeout` 命令，用 `curl -m 60` 限时 |
