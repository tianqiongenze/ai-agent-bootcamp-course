| 实验环境 | 课程仓库（pytest/k6/Playwright 工具链）、CI 门禁 |

## 一、实验目标

1. 【应用】为本学期自己的改动补 2 个单测，覆盖率门禁（80%）通过（对应课程标准 LF6 企业任务）。
2. 【分析】执行一次 k6 阶梯压测并判读拐点。
3. 【理解】跑一次班级评测集，理解 bootstrap CI 的意义（教授方法学）。

## 二、环境与准备

- 前置：本组学期内合并的 PR 清单（选 2 个核心改动）。
- 工具链：pytest + coverage、k6（教师提供课程集群内压测机）、评测集 CLI。
- 纪律：压测目标限课程命名空间服务；RPS 上限遵守教师发放的配额（容量诚实）。

## 三、实验步骤

### 步骤 1：补单测过门禁（50′）

```bash
# 定位缺口：看覆盖率报告中标红的分支
pytest --cov=packages --cov-report=term-missing
# 为选定改动编写 2 个测试（建议：1 个正常路径 + 1 个边界/异常路径）
pytest tests/test_l15_teamXX.py -v
```

✓ 验证点：CI 门禁全绿截图（覆盖率 ≥80%，基线 48 测不回归——参考 dap-v2 工程基线口径）。

### 步骤 2：k6 阶梯压测与拐点判读（40′）

1. 执行教师发放的阶梯脚本（如 20→60→100→140→180 RPS 各 2 分钟）。
2. 记录各档 P95 时延与错误率：

| 档位 RPS | P95 (ms) | 错误率 |
|---|---|---|
| 20 |  |  |
| 60 |  |  |
| 100 |  |  |
| 140 |  |  |
| 180 |  |  |

3. 判读：拐点在哪一档？依据是什么曲线特征（P95 陡增 / 错误率起跳）？

✓ 验证点：k6 原始输出入库 + 判读结论一段。

### 步骤 3：评测集与 bootstrap CI（20′）

1. 跑班级评测集（held-out），记录准确率与均时延。
2. 用教师脚本做 bootstrap 重采样，输出 95% CI。
3. 回答：为什么"91.7%"必须带着"CI 79.2–100%"一起说？（小样本评测的诚实口径）

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 测试全绿但门禁失败 | 覆盖率未达 80%；补测缺口分支而非堆凑数测试 |
| k6 把服务打挂 | 阶梯超配额；降档重跑并记录（这本身是容量诚实素材） |
| CI 准确率 100% 但抽测错 1 题 | 检查评测集是否泄漏进 few_shots；held-out 必须隔离 |
