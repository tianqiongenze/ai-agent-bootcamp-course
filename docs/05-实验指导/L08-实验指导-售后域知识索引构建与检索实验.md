## 一、实验目标

1. 【应用】为售后域构建三类知识条目：表元数据、口径说明、few-shot 示例。
2. 【分析】通过对比实验说明"为什么纯向量检索会翻车"（学生讲堂③素材）。
3. 【应用】验证语义缓存命中（cosine≥0.92）的行为边界。

## 二、环境与准备

- 知识条目格式：课程仓库 `knowledge/` 目录规范（三类条目各一个示例）。
- 前置：L02 售后域表结构设计已评审通过（未通过的先补）。
- 警示（来自项目真实教训）：**候选表+字段注入曾使评测从 91.7% 倒退到 75%**——上下文宁精勿滥，本实验不注入候选列表，靠精准元数据。

## 三、实验步骤

### 步骤 1：撰写三类知识条目（50′）

| 条目类型 | 售后域示例 | 质量要求 |
|---|---|---|
| 表元数据 | `dwd_cs_ticket_di`：粒度=1 工单 1 行；主键 ticket_id；常用列处置时长/门店/品类 | 字段口径必须与 DDL 一致 |
| 口径说明 | "处理时长 = 完结时间 - 受理时间，剔除节假日按工作日口径" | 一条口径一句话，可被检索命中 |
| few-shot 示例 | 问："上月各门店退换货率" → 正确 SQL 全文 | SQL 必须在沙箱验证通过后才可入库 |

✓ 验证点：条目总量 ≥9 条（三类各 ≥3）；每条经组间交叉检查（口径 vs DDL 一致性）。

### 步骤 2：建索引并检索验证（30′）

```bash
# 按课程工具链重建向量索引（命令由知识引擎 README 给出）
make knowledge-rebuild
# 检索冒烟：3 条售后域问句应命中正确条目
curl -m 30 -H "x-internal-token: $TOKEN" .../kb/search?q=退换货率口径
```

✓ 验证点：3 条问句检索命中截图（命中条目 ID + 得分）。

### 步骤 3：纯向量 vs 混合对比实验（30′）

固定 5 条含精确术语的问句（如 "ads_cs_sla_day 表的 SLA 口径"），分别在"仅向量"与"向量+关键词兜底"两种检索配置下记录命中 Top1：

| 问句 | 纯向量 Top1 | 混合 Top1 | 差异原因 |
|---|---|---|---|
|  |  |  |  |

结论题：精确术语（表名/字段名）为什么更适合关键词/精确匹配路径？

### 步骤 4：语义缓存边界（10′）

对同一问句做 3 次同义改写（如"上月门店退换货率是多少"），观察缓存命中与不命中，记录 cosine 值，验证 0.92 阈值行为。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| few-shot 示例入库后 LLM 无视照错 | 14b 模型已知问题：不要指望 few-shot 纠偏，改走 FAQ 直答（L09 内容） |
| 检索得分普遍偏低 | chunk 粒度切太碎/太大；按条目类型调整 chunk 策略后重建索引 |
| 缓存命中了错误答案 | 先查该缓存写入时间与知识库版本——知识库更新后必须失效缓存 |
