# 实验 L03：ADR 精读与架构图重绘

**（实验指导 ｜ 对应学习情境 L03 ｜ 企业站 2 学时 ｜ 实验③）**

| 项 | 内容 |
|---|---|
| 实验类型 | 阅读理解 + 架构表达 |
| 实验环境 | 课程仓库 `docs/07-项目资源/adr/`（ADR-001~004）、SAD.md |
| 分组 | 结对 + 组内分工（每组认领 1 份 ADR 深读） |
| 提交物 | 架构说明/勘误 PR + 学生讲堂①讲稿 |

---

## 一、实验目标

1. 【分析】精读 1 份 ADR，还原其"背景→选项→决策→后果"论证链。
2. 【分析】对照 SAD 六层架构，画出（或修正）本组理解的架构图。
3. 【素养】在学生讲堂用 3 分钟向同伴讲清 1 份 ADR（费曼）。

## 二、环境与准备

- 材料：`ADR-001-reuse-shared-infra.md`（复用共享基建）、`ADR-002-orchestration-engine.md`（自研编排）、`ADR-003-v2-parallel-to-v1.md`（双轨并行）、`ADR-004-capacity-honesty.md`（容量诚实）。
- 工具：draw.io / Excalidraw / 纸笔均可，导出 PNG 入库。

## 三、实验步骤

### 步骤 1：ADR 精读（40′）

按四问法拆解认领的 ADR，填写《ADR 解剖卡》：

| 四问 | 我的回答 |
|---|---|
| 当时要解决什么问题？（背景与约束） |  |
| 有哪些备选方案？各自被否的理由？ |  |
| 最终决策是什么？代价（trade-off）是什么？ |  |
| 这个决策今天看还对吗？举 1 个会推翻它的变化 |  |

✓ 验证点：解剖卡第 3 问必须写出"代价"——只写收益视为未读懂。

### 步骤 2：架构图重绘（30′）

1. 通读 SAD.md 六层架构（控制台→网关→编排→Agent→知识引擎→工具/数据平台）。
2. 重绘架构图，**必须标注**：Agent 间调用要经过的内部认证头位置、NL2SQL 五步管线发生的位置、四层护栏入口。
3. 与原架构图 diff：发现 SAD 未画清/画错之处，作为"勘误项"记录。

✓ 验证点：架构图中至少有 3 处本组自行补强的标注。

### 步骤 3：提交 PR 与讲堂准备（10′）

- PR 内容：本组架构图 PNG + 《ADR 解剖卡》md，或对课程资料架构说明的勘误建议。
- 下周学生讲堂①：每组 3 分钟讲 1 份 ADR（用 EVAL-03 量表互评）。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 把 ADR-004 读成"不允许压测" | 误读。容量诚实是"用单副本实测线性外推"而不是"拍脑袋承诺并发"；压测照做，承诺要讲口径 |
| 架构图只画组件不画数据流 | 架构图无数据流等于地图无道路；每条线标注"数据/指令/事件" |
| 勘误 PR 语气像"挑错" | 工程勘误对事不对人：引用原文行号 + 建议改法 |

## 五、提交物与验收标准

| 提交物 | 验收标准 |
|---|---|
| 《ADR 解剖卡》 | 四问齐全，第 3 问含代价分析 |
| 架构图 PNG | 六层齐全 + 3 处以上自研标注 |
| PR | 合并通过，勘误项（若有）被导师采纳或书面说明不采纳理由 |
