# 实验 L13：ETL 编排 Agent 与人机协作审批

**（实验指导 ｜ 对应学习情境 L13 ｜ 企业站 2 学时 ｜ 实验⑬）**

| 项 | 内容 |
|---|---|
| 实验类型 | 设计性 + 流程演练 |
| 实验环境 | 课程环境 ETL 编排 Agent（人审界面）、DAG 配置 |
| 分组 | 结对（一人扮 Agent 侧，一人扮人审侧，互换） |
| 提交物 | ETL 草稿 PR（需求→DAG→SQL→审批全链路记录） |

---

## 一、实验目标

1. 【应用】走通"需求描述→模型推荐→SQL 生成→DAG 配置→人审→入库"全流程（对应课程标准 LF5 企业任务）。
2. 【评价】论证"Agent 只建议不执行"的人机协作边界（学生讲堂⑤素材）。
3. 【应用】验证质量规则随 ETL 附带生成机制。

## 二、环境与准备

- 实验需求样题（自选 1 条）：从售后域提一个每日汇总需求，如"每日门店退换货率汇总表"。
- 提醒：Agent 生成的 SQL 与 DAG **一律视为草稿**；人审通过前不落生产调度。

## 三、实验步骤

### 步骤 1：需求描述与模型推荐（30′）

1. 用业务语言写需求（含：来源表、口径、频率、下游用途）。
2. 观察 Agent 推荐的模型/表映射，核对：推荐是否引用了 L08 建的元数据？推荐错了记下来（这是知识库质量反馈）。

### 步骤 2：SQL 生成与人工核查（40′）

1. Agent 生成 SQL 草稿 → 人审重点五查：

| 查什么 | 查法 |
|---|---|
| 口径正确 | 对照需求原文逐句核对 |
| 增量/全量 | 与刷新声明一致 |
| 分区裁剪 | WHERE 命中分区键 |
| 语法与只读 | sqlglot 校验通过；无写操作 |
| 成本 | EXPLAIN 预估行数合理 |

2. 修改意见回传 Agent 重新生成（体验一轮"人机对话式"修正）。

✓ 验证点：最终 SQL 在沙箱执行通过 + EXPLAIN 截图。

### 步骤 3：DAG 配置与人审（30′）

1. 核对 Agent 生成的 DAG：调度频率、上游依赖、失败重试、超时、告警接收人。
2. 人审通过 → 提交审批留痕；同时检查"质量规则附带生成"是否就位（本任务至少附带 2 条 L11 式规则）。

✓ 验证点：DAG 图截图 + 审批留痕截图。

### 步骤 4：PR 整理（10′）

- 入库：需求文档、最终 SQL、DAG 配置、审批记录、五查记录。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 人审直接"看一眼就过" | 五查记录为空视同未审；审批不是签字是核查 |
| Agent 推荐 SQL 引用不存在的表 | 知识库元数据缺失/过期；回到 L08 修正知识条目 |
| DAG 无失败告警配置 | 静默失败是事故温床；按模板补齐告警项 |

## 五、提交物与验收标准

| 提交物 | 验收标准 |
|---|---|
| ETL 草稿 PR | 全链路记录齐全；五查表非空 |
| 沙箱证据 | SQL 执行 + EXPLAIN |
| 附带质量规则 | ≥2 条且与任务匹配 |
