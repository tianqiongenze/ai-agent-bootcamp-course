## 一、实验目标

1. 【理解】还原 420ms 直答案例的链路（元数据断路：跳过检索与 LLM，精确命中示例库直接回 SQL）。
2. 【应用】走通"错误回答 → 人工修正 → 写入 few_shots → 增量索引 → 同题直答"全闭环。
3. 【评价】能论证"知识引擎是 Agent 效果的天花板"（课后费曼题目）。

## 二、环境与准备

- 背景事实：v2-r12 评测 12/12=100% 中，FAQ 直答贡献显著（问题精确命中人工修正示例时零推理零时延，model=faq-hit）。
- 分工：一人扮"业务用户"提问，一人扮"数据工程师"做修正，角色互换一轮。

## 三、实验步骤

### 步骤 1：首问与错误观察（20′）

提一条知识库未覆盖问句（如"上月华东售后工单平均处理时长"），记录：

```
首问结果：SQL / 行数 / model 标记 / 是否正确（对照手工 SQL）
错误点：<列名错 / 口径错 / 表错>
```

### 步骤 2：人工修正与回流（50′）

1. 工程师侧打开反馈通道，提交修正后的正确 SQL（必先在沙箱验证通过）。
2. 确认修正示例进入 `few_shots` 且触发增量索引（不重建全量）。
3. 用**完全相同的问句**再次查询：

✓ 验证点：第二次查询日志显示 `model=faq-hit`、时延 <1s（贴前后两次日志对比截图）。这就是"人工修正一次，同类问题永久正确"。

### 步骤 3：近似问句实验（20′）

- 同义改写问句 2 条，观察是否仍命中直答（精确匹配边界）。
- 结论：直答靠**精确命中**，近似问句走什么路径？把观察到的路径写下来。

### 步骤 4：闭环流程图（10′）

画出本实验的闭环：提问→错误→修正→沙箱验证→few_shots→增量索引→直答。标注哪一步最容易被跳过、跳过的后果。

## 四、常见坑与排障

| 现象 | 原因与处置 |
|---|---|
| 修正后同题仍走 LLM | 增量索引未触发/问句不一致（多了句号都算不同问句）；核对精确匹配键 |
| 直答返回的 SQL 早已过期 | 口径变更未同步知识库——知识库是活文档，修正时同步口径说明 |
| 把 faq-hit 误当"缓存命中" | 两者不同：语义缓存按相似度（cosine≥0.92），直答按精确命中示例库 |
