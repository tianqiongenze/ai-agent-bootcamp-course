## 一、课程定位与设计理念

### 1.1 课程定位

本课程面向**数据平台工程师、数据智能应用开发工程师**岗位群，以一个真实投产的 AI 数据中台项目（DAP-v2）为完整载体，覆盖"架构规划 → 基础设施 → 智能查询 → 质量治理 → ETL 编排 → 测试发布"全生命周期。学生结课时具备：在 Kubernetes 集群上，运用大语言模型与多智能体技术，独立交付一套"自然语言查数 + 数据质量自愈 + ETL 自动生成"的数据中台服务的能力。

### 1.2 德国双元制本土化设计（Duale Ausbildung）

| 双元制要素 | 本课程落地方式 |
|---|---|
| **双学习场所**（Lernort） | 校内理实一体教室（理论/演示/仿真）＋ 企业实训站（真实 2 节点 K8S 集群、真实项目仓库 dap-v2） |
| **双导师** | 校内导师（方法论、原理、复盘）＋ 企业导师（工程标准、代码评审、上线把关） |
| **学习领域**（Lernfeld） | 打破学科体系，按**工作过程**重组为 6 个学习领域（见 §三） |
| **学习情境**（Lernsituation） | 每讲 = 一个来自 DAP-v2 真实任务的学习情境（含"客户委托单"式任务描述） |
| **行动导向**（Handlungsorientierung） | 每情境遵循 **资讯→计划→决策→实施→检查→评价** 六步法（完整工作过程） |
| **IHK 式考核** | 过程性任务单 + 项目作品 + 专业对话（Fachgespräch）答辩，弱化一次性笔试 |

### 1.3 教学方法论

| 方法 | 用途 | 落地环节 |
|---|---|---|
| **费曼学习法**（Feynman Technique） | 以教代学：学生必须把学到的东西讲给别人听、讲得明白才算掌握 | 每讲固定 20 分钟"**学生讲堂**"环节；期末"费曼答辩"：学生用 10 分钟向"非技术评委"（跨专业学生扮演的业务方）讲清一个子系统 |
| **布鲁姆认知分类**（Bloom's Taxonomy） | 目标分层：记忆→理解→应用→分析→评价→创造 | 每个学习情境的教学目标按六层标注（见 §三目标矩阵）；考核题与任务按层级命题 |
| **项目驱动**（PBL） | 全程围绕 dap-v2 真实仓库真实代码 | 每周企业实践直接向课程仓库提交 PR |
| **结对编程 / 代码评审** | 企业工程文化内化 | 企业站实践 2 人结对 + 导体评审 |

### 1.4 课程思政

以"数据要素安全流通"为主线：数据安全法/个人信息保护视角下的 PII 脱敏实践（LF5）、自主可控技术栈（国产 TiDB）选型讨论、工程师职业操守（审计留痕、诚实报告缺陷——HSA 文化）。

## 二、课程目标（按布鲁姆层级）

### 2.1 知识目标（记忆/理解）
1. 【记忆】说出数据中台四层/五层架构（接入-编排-知识-工具-数据平台）各层职责与边界。
2. 【记忆】列出 NL2SQL 五步管线（Schema Linking→检索→生成→自校验→沙箱执行）与四层安全护栏（语法/资源/权限/审批）。
3. 【理解】解释读写分离、多级缓存（L1/L2/L3）、事务性 Outbox、DLQ 死信等机制的原理与适用场景。
4. 【理解】说明双元制六步工作法与敏捷迭代在本项目中的对应关系。

### 2.2 能力目标（应用/分析）
5. 【应用】在 K8S 集群上部署/扩容 TiDB、CRDB、Milvus、Pulsar、Redis 全套数据基础设施并完成健康验证。
6. 【应用】使用 sqlglot 实现 SQL 只读白名单与 PII 列脱敏；使用 LiteLLM 网关路由多 LLM。
7. 【分析】对一次 NL2SQL 失败案例（评测集错题）进行根因定位（知识库/提示词/Schema Linking）并给出改进方案。
8. 【分析】阅读 dap-v2 生产代码，画出洞察 Agent 的完整执行路径并标注护栏拦截点。

### 2.3 素养目标（评价/创造）
9. 【评价】依据测试报告（k6 压测/覆盖率/评测 CI）评判一次发布的质量门槛是否达标，并撰写发布决策建议。
10. 【创造】以团队为单位，在 dap-v2 上扩展一个新能力（如新 Agent / 新图表类型 / 新数据域），完成"设计→编码→测试→答辩"全流程。
11. 【评价/素养】践行"诚实自评"工程文化：如实标注 DEFERRED 与已知缺陷，不虚报完成度。

## 三、学习领域与内容标准

> 每个学习领域（LF）对应 DAP-v2 项目的真实模块；括号内为布鲁姆主层级与学时。

### LF1 数据中台认知与数仓架构规划（理解 | 12 学时）
- 业务痛点：临时取数需求排队 2 天（资料[1]§1.1）
- 数仓分层 ODS→DWD/DIM→DWS→ADS；Data Agent 四层模型
- DAP-v2 六层架构总览与 ADR 架构决策记录阅读
- 零售数仓数据集（105 万订单）结构解读
- **企业任务**：为新业务域（如"售后域"）规划分层表结构

### LF2 平台基础设施搭建与运维（应用 | 18 学时）
- K8S 核心对象回顾：Deployment/HPA/ConfigMap/Secret/Ingress/PDB/NetworkPolicy
- GitOps 声明式部署与漂移检测（DGO）
- TiDB（HTAP 数仓）、CRDB（平台库+读写分离）、Milvus（向量+语义缓存）、Pulsar（任务队列+DLQ）部署与验证
- 容量诚实口径：单副本容量→线性外推公式（ADR-004）
- **企业任务**：为集群扩容一个 worker 节点并验证 HPA 生效

### LF3 智能查询服务开发：NL2SQL 与知识引擎（应用/分析 | 18 学时）
- NL2SQL 管线：意图理解→Schema Linking（列级反向索引）→LLM 生成→自校验→沙箱执行
- RAG 混合检索：Milvus 向量 + CRDB 关键词 + 精确匹配三层；chunk 粒度策略
- 语义缓存（cosine≥0.92）与 FAQ 直答（人工修正回流，420ms 直答实例剖析）
- LLM 降级链：主模型→备模型→确定性模板（DPC）
- **企业任务**：为"售后域"扩充知识库索引并跑通 3 条新问句

### LF4 数据质量治理 Agent（分析/评价 | 12 学时）
- 规则引擎为主、LLM 为辅的混合模式（资料[2]§3.4）
- 五类规则：空值率/值域/新鲜度/行数波动/唯一性；质量扫描→根因溯源（血缘）→修复建议→审批闭环
- NebulaGraph 血缘与 CRDB 双写兜底
- **企业任务**：为售后域设计 4 条质量规则并触发一次巡检

### LF5 ETL 编排 Agent 与安全护栏（评价/创造 | 12 学时）
- 需求→模型推荐→SQL 生成→DAG 配置→人机协作审核
- 四层护栏代码级剖析：sqlglot AST 白名单 / 强制 LIMIT / 租户表授权 / 审批工作流
- PII 启发式脱敏的词边界设计（误杀/漏杀权衡案例）
- bcrypt 密码哈希与 Secret 管理（SCS 铁律）
- **企业任务**：提交一个会被护栏拦截的 PR 并解释拦截层

### LF6 测试、性能验证与发布运维（评价/创造 | 18 学时 + 答辩 6 学时）
- TDD/BDD/SDD：pytest 覆盖率门禁 80%（TCG）
- Playwright 无头端到端；k6 阶梯压测与拐点判读；NL2SQL 评测集与 bootstrap CI（教授方法学）
- 混沌降级验证（Redis 故障注入）；优雅关停与备份恢复（20MB NFS 备份产物）
- 发布决策：readyz 全绿 + 门禁通过才可上线
- **综合项目答辩**（费曼式）

## 四、教学实施建议

1. **六步法节奏**（每讲 4 学时校内）：资讯 30′→计划 30′→决策 20′→实施 90′→检查 40′→**评价+学生讲堂 30′**（费曼）。
2. **企业站 2 学时**：真实 dap-v2 仓库分支上完成任务，企业导师按工程标准评审 PR（代码规范/测试/文档三查）。
3. **评测驱动**：课程内置"班级评测集"，学生提交的改进跑评测集看准确率变化——用数据说话（HSA）。
4. **诚实文化**：所有实验报告必须含"未验证/未完成清单"栏，虚报按 0 分处理并要求重做。

## 五、考核评价（IHK 式过程考核）

| 考核项 | 占比 | 形式 | 评价主体 |
|---|---|---|---|
| 实训任务单（16 次） | 30% | 六步法任务工单（资讯/计划/实施/检查自评） | 校内导师 |
| 企业站实践（PR 评审） | 15% | 代码提交质量、评审通过率 | 企业导师 |
| **费曼学生讲堂** | 10% | 每讲 30′随机抽讲 + 同伴互评量表 | 师生共评 |
| 项目里程碑（3 次） | 15% | LF2/LF4/LF6 结点的作品验收 | 双导师 |
| 综合项目与**费曼答辩** | 20% | 团队作品 + 10 分钟"讲给业务方听" + 专业对话 | 答辩组（含企业） |
| 理论笔试 | 10% | 布鲁姆分层命题（记忆/理解/分析/评价 4 档） | 校内导师 |

**及格线**：总评 ≥60 且综合项目答辩 ≥50。**里程碑补考**：未达标里程碑可在下一周补做，最多 2 次。
