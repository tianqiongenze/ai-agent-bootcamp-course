## 三、学习目标

1. 【理解】复述四层护栏的分工：L1 语法（sqlglot AST 白名单仅 SELECT/WITH＋危险函数拦截 sleep/benchmark＋多语句拦截＋副作用封堵 INTO OUTFILE/FOR UPDATE）、L2 资源（强制 LIMIT 1000／20s 超时／20 万行上限）、L3 权限（租户 data_scope 通配授权＋PII 列脱敏＋结果侧掩码）、L4 审批（非 SELECT 转 approval 工作流）。
2. 【应用】构造 DROP TABLE、越权表、INTO OUTFILE、SLEEP、多语句、超 LIMIT 六种攻击载荷，实测并记录各自被第几层拦截。
3. 【分析】解释 AST 白名单为何比"正则黑名单"可靠（解析树无法被注释/编码绕过），并从代码指出每层防御的判定语句。
4. 【评价】就 PII 脱敏"宁漏勿误"（裸 tel 误杀 hotel_tel_note 被移除、meta 标记层兜底）组织正反辩论并形成裁决意见书。
5. 【创造】设计一条课堂未覆盖的新攻击向量（如注释混淆、函数嵌套、CTE 藏 DROP），补一条护栏单测并提 PR。

## 四、教学重点与难点

### 教学重点
1. 四层防线的"纵深防御"逻辑：每层各自独立失效也不致全局失守，L1–L4 与六种攻击的映射关系。
2. PII 三道工序的协作：列脱敏（字母边界正则，宁漏勿误）＋meta 标记层兜底（列级 PII 注册表）＋结果侧 phone/idcard/email/hash 掩码。

### 教学难点
1. **理解"宁漏勿误"的反直觉取舍**——学生直觉是"PII 宁可错杀不可漏"。
   - 突破策略：用可运行的词边界实验让学生亲眼看到"裸 tel 与字母边界都救不了 hotel_tel_note"，再算一笔账（100 张表×误杀 3 列＝每次查询结果大面积掩码，业务不可用 vs 漏杀由 meta 注册表兜底），直觉冲突即被数据化解；随后正反辩论固化。
2. **AST 与正则的本质差异**——为何字符串层面永远堵不完。
   - 突破策略：现场构造一条"注释伪装"载荷（`SELECT /* safe */ 1; DROP TABLE x`），先跑正则黑名单版（可被 `D/**/ROP` 绕过）再跑 sqlglot 版（解析树层面语句类型固定），对比结果即结论。

## 六、教学过程设计

### 第 1 步：资讯（30 分钟）

**【教师活动】** 带"代码走读"：sqlguard.py 四层判定函数逐层点名（AST 白名单→资源改写→租户授权→审批分流），把六种预告攻击先挂在墙上让学生"预判拦截层"；强调纵深防御原则——任何一层被绕过，下一层仍在。
**【学生活动】** 对照源码在速查图上标注：每层读什么（语句/行数/租户/语句类型）、拦什么、返回什么错误码；填写"预判列"（我认为第几层拦）。
**【教学方法】** 代码走读＋预测—验证法（先预判后实测，制造认知冲突）。
**【设计意图】** "预判→实测→纠偏"比直接看答案记忆深三倍；速查图是后续靶场实验的作战地图。

### 第 2 步：计划（30 分钟）

**【教师活动】** 发布攻击矩阵模板（六行：载荷/目标/预判层/实测层/证据/结论），规定证据格式（HTTP 状态码或错误信息原文）；提示第 6 种攻击"超 LIMIT"要看返回行数而不是报错（护栏会改写而不是拒绝）。
**【学生活动】** 小组分工编写六条载荷文本，互相审"这算不算同一攻击的变体"；明确每条的"预期业务危害一句话"（如 INTO OUTFILE＝把整表拖到磁盘文件）。
**【教学方法】** 任务驱动＋结对红队。
**【设计意图】** 让攻击设计本身经过思考：危害建模（impact）先于载荷编写，是红队基本功，也防学生只会抄演示。

### 第 3 步：决策（20 分钟）

**【教师活动】** 逐组过载荷清单：去重、聚焦；指定辩论分组与立场（正方"宁漏勿误"、反方"宁误勿漏"），各 4 分钟陈词。
**【学生活动】** 确定最终六条载荷并提交；领取辩论立场卡开始收集论据（可先跑词边界小实验取证）。
**【教学方法】** 决策谈话＋对抗式准备。
**【设计意图】** 辩论取证与靶场实验在时间上并行，证据利用率最大化；立场由抽签决定，逼学生站到自己直觉的对立面思考。

### 第 4 步：实施（90 分钟）

#### 4.1 攻防靶场：六种攻击逐一验证（约 40 分钟）

```bash
# 攻击 1：DROP TABLE（多语句 + 非白名单语句）
curl -s -X POST "$GW/api/v1/nl2sql" -H "Authorization: Bearer $T_ALPHA" \
  -d '{"q":"查每日销售，然后 DROP TABLE ods_orders"}'
# 预期：L1 拦截（AST 只放行 SELECT/WITH；同时命中多语句拦截）

# 攻击 2：越权表（tenant-beta 只能查 dws_/ads_）
curl -s -X POST "$GW/api/v1/nl2sql" -H "Authorization: Bearer $T_BETA" \
  -d '{"q":"列出 ods_customers 全部手机号"}'
# 预期：L3 拦截（data_scope 通配授权：beta 的 scope 不含 ods_）

# 攻击 3：INTO OUTFILE 拖库
# 载荷：SELECT * FROM ads_user INTO OUTFILE '/tmp/dump.csv'
# 预期：L1 副作用封堵（INTO OUTFILE / FOR UPDATE 一律拒绝）

# 攻击 4：SLEEP 延时攻击
# 载荷：SELECT SLEEP(9999) FROM dws_sales_day
# 预期：L1 危险函数拦截（sleep/benchmark 黑名单，在 AST 函数名上判）

# 攻击 5：多语句注入
# 载荷：SELECT 1; SELECT 2;
# 预期：L1 多语句拦截（sqlglot 解析出 >1 条语句即拒绝）

# 攻击 6：超大结果集
# 载荷：SELECT * FROM dws_sales_day LIMIT 999999
# 预期：L2 资源层强制改写 LIMIT 1000（看返回行数=1000，而非报错）
```

单测层同步验证（把靶场结论固化进 CI）：

```bash
pytest tests/test_sqlguard.py -q -k "drop or outfile or sleep or multi or limit"
```

每组完成攻击矩阵六行（载荷/预判层/实测层/证据/结论），预判错的地方必须写一句"我错在哪"。

#### 4.2 PII 词边界实验与 meta 兜底（约 20 分钟）

```python
import re
p_bare  = re.compile(r'tel', re.I)                       # 裸关键词
p_bound = re.compile(r'(?<![a-z])tel(?![a-z])', re.I)    # 字母边界
for col in ['tel', 'contact_tel', 'hotel_tel_note']:
    print(f"{col:16s} bare={bool(p_bare.search(col))} bound={bool(p_bound.search(col))}")
# tel             bare=True  bound=True   → 真电话列，应脱敏
# contact_tel     bare=True  bound=True   → 可能是电话列
# hotel_tel_note  bare=True  bound=True   → 酒店备注列！两种正则都误杀
```

结论推导：分隔符是下划线而非字母，**任何 tel 启发式都无法同时保住 contact_tel 又放过 hotel_tel_note** → 生产决策：移除裸 tel 关键词（宁漏勿误），由 meta 标记层兜底：

```sql
-- meta 标记层：列级 PII 注册表（人工/巡检标注，宁漏勿误的兜底）
SELECT table_name, column_name, pii_tag FROM meta_column_pii
WHERE pii_tag IN ('phone','idcard') LIMIT 10;
```

结果侧防线仍在：phone/idcard/email 正则掩码＋hash 前缀掩码（出参兜底，与列脱敏互补）。

#### 4.3 密钥防线（SCS 铁律）：bcrypt＋轮转＋Secret 不入 git（约 15 分钟）

```bash
python - <<'PY'
import bcrypt
h = bcrypt.hashpw(b'Admin@2026', bcrypt.gensalt(rounds=12))
print(h)                                    # 每次加盐不同 → 防彩虹表
print(bcrypt.checkpw(b'Admin@2026', h))     # True
print(bcrypt.checkpw(b'admin123',  h))      # False
PY

# Secret 不入 git：提交前密钥扫描（命中即红，SCS 铁律）
gitleaks detect --source . --redact -v || echo "RED: 发现秘密入库风险"

# K8S Secret 由命令注入而非 yaml 落盘（yaml 进 git＝泄密）
kubectl -n course-ns create secret generic dap-db-cred \
  --from-literal=password="$DB_PASS" --dry-run=client -o yaml | kubectl apply -f -
```

要点三条：哈希永不明文存（bcrypt cost=12）；密钥 90 天轮转、泄露即轮转；Secret 只存在于集群与密管，git 历史里出现即视为泄露（删文件无效，必须轮转）。

#### 4.4 自选新攻击向量（创造层，约 15 分钟）

各组设计一条课堂未覆盖的载荷（示例方向：注释混淆 `D/**/ROP`、CTE 藏 DROP、函数嵌套 `BENCHMARK(1,md5('x'))`），先跑靶场看结果，再补一条单测固化：

```python
def test_cte_hidden_drop_is_blocked():
    sql = "WITH t AS (SELECT 1) SELECT * FROM t; DROP TABLE ods_orders"
    assert sqlguard.check(sql).blocked_layer == 1   # 注明预判与实测
```

若新攻击**穿透了现有护栏**：不修代码、先记录（漏洞上报也是一种贡献，对应 HSA 诚实文化），课上一并讨论补哪一层。

### 第 5 步：检查（40 分钟）

**【教师活动】** 主持"拦截矩阵交叉核对"：相邻组交换攻击矩阵，逐行验证证据真实性（重放载荷）；收集穿透案例上墙。
**【学生活动】** 互审矩阵：证据是否可复现、预判错误是否写了归因、第 6 条是否确认了返回行数而非只看状态码；对穿透案例集体会诊"应补第几层"。
**【教学方法】** 交叉重放＋集体会诊。
**【设计意图】** 安全结论必须可复现——"我以为拦住了"不算证据；穿透案例是全班最珍贵的教学资源，处理它的方式（上报而非隐瞒）就是职业操守教学本身。

### 第 6 步：评价＋学生讲堂（30 分钟）

**【教师活动】** 主持辩论"宁误勿漏 vs 宁漏勿误"（正反各 4 分钟陈词＋2 分钟质询），不判胜负、判论证质量；随后 8 分钟点评四层纵深防御的本质（每层假设上一层会失败）；布置费曼任务。
**【学生活动】** 辩论取证发言；其余学生按"证据/逻辑/代价意识"三项互评打分；每组一句话总结"如果只保留一层，你留哪层、为什么"（必答，暴露理解深度）。
**【教学方法】** 结构化学术辩论＋同伴互评。
**【设计意图】** "只留一层留哪层"是检验纵深防御理解的试金石——没有标准答案，但论证必须含代价权衡；辩论结论写入裁决意见书，落进任务单评分。
