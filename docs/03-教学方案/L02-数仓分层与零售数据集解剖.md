## 二、任务描述

某零售集团数据部收到运营部委托：为"售后域"（退换货）统一分析口径。退换货数据散落在 ods_orders 明细与客服工单里，运营要"退款率"、财务要"退款金额"、客服要"二次进线率"，三处数字对不上。要求数据部按数仓分层规范设计售后域 ODS→DWD/DIM→DWS→ADS 表，并书面说明"同一指标在哪层算、为什么"。

## 三、学习目标

1. 【理解】能画出 ODS/DWD/DIM/DWS/ADS 分层结构图，并对每层说出"一个职责、一条纪律、一个反例"（如 ODS 纪律：原样贴源不改业务含义）。
2. 【理解】能用 dap-v2 零售数仓真实表链路（ods_orders 105.9 万→dwd_trade_order_detail 101 万→dws_store_daily_sales 19 万→ads_store_gmv_trend）解释数据自下而上的"收敛"过程与行数变化原因。
3. 【应用·渗透】给定 5 个业务问题（如"上月各门店退款率""订单 A 为何退款"），能用三问法正确判定"应在哪层回答"并指出所用表与关键字段，判断正确率 ≥4/5。
4. 【分析·渗透】能指出"直接在 ODS 上算 GMV"反例的三类风险（口径漂移、性能、复用性），并结合 105.9 万行数据量说明性能代价。
5. 【创造·渗透】完成《售后域分层设计说明书》初稿：至少 4 张表、每表含表名/粒度声明/主键/核心度量/来源映射。

## 四、教学重点与难点

### 教学重点

1. 各层职责边界与建模纪律：ODS 贴源留痕、DWD 明细事实（清洗＋维度关联，行=业务过程一次发生）、DIM 一致性维度（全公司共用的门店/商品口径）、DWS 主题汇总（行=主体×周期）、ADS 应用导向（直接喂报表）。
2. 粒度声明（grain）先行——每张表动手前先回答"一行是什么"；粒度定了，主键、度量、来源全部随之确定。

### 教学难点（附突破策略）

1. **"同一问题在哪层答"的判断**——学生常把"能在哪层算"当成"该在哪层算"。
   突破策略：三问法口诀——①要明细还是汇总？②跨不跨主题/部门？③给谁看、看多快？配套五道真实题推演，每题先判层再写伪 SQL，最后用 DAP-v2 控制台 NL 查数交叉验证答案一致性。
2. **售后域从零设计分层（无标准答案）**——学生面对空表设计文档无从下手。
   突破策略：提供"分层表设计模板"（表名/粒度/主键/度量/来源五栏），并以交易域成熟表 dwd_trade_order_detail 为类比锚点做迁移：交易域怎么洗订单，售后域就怎么洗退款单。

### 6.1 资讯（30′）

- 【教师活动】宣读运营部委托单（投影三个对不上的数字：运营说退款率 3.2%、财务说 2.1%、客服说 4.0%），抛出主问题："同一件事为什么有三个数？"随后带学生用真实 DDL 认识五张表：

```sql
SHOW CREATE TABLE ods_orders\G
SHOW CREATE TABLE dwd_trade_order_detail\G
SHOW CREATE TABLE dim_store\G
SHOW CREATE TABLE dws_store_daily_sales\G
SHOW CREATE TABLE ads_store_gmv_trend\G
```

- 【学生活动】对照表字典逐表记录：字段清单、主键、可猜出的粒度（一行是什么）；登记关键疑点到记录单。
- 【教学方法】案例导入＋结构化阅读（DDL 即"图纸"）。

表字典阅读三步法（板书）：先读表注释与主键猜粒度→再 diff 上下游字段找清洗点→最后 COUNT 行数验证收敛假设。
- 【设计意图】从真实矛盾（口径不一）出发，让分层规范成为"解题需要"而非背诵条目。

**分层职责与纪律速查表（资讯环节板书留存，全程可查）**

| 层 | 职责 | 一条纪律 | 反例警示 |
|---|---|---|---|
| ODS | 原样贴源、留痕可回溯 | 不改业务含义，只加装载元数据 | 在 ODS 上直接建业务报表 |
| DWD | 明细事实：清洗＋维度关联 | 先声明粒度（一行=一次业务过程） | 把门店名冗余成字符串不建维表 |
| DIM | 一致性维度，全公司同口径 | 缓慢变化要有处理规则 | 各部门各养一份"门店表" |
| DWS | 主题汇总，面向复用 | 粒度=主体×周期，度量可加总 | 给业务直连查数（绕过服务层） |
| ADS | 应用导向，直接喂报表 | 指标口径冻结并登记 | 又在 ADS 里 join 回明细 |

### 6.4 实施（90′）

#### 子步骤 1：五表解剖（30′）

逐表执行并填《表解剖记录单》：

```sql
SELECT COUNT(*) FROM ods_orders;             -- ≈ 1,059,000（105.9 万原始订单）
SELECT COUNT(*) FROM dwd_trade_order_detail; -- ≈ 1,010,000（101 万清洗后明细）
SELECT COUNT(*) FROM dws_store_daily_sales;  -- ≈ 190,000（19 万 门店×日 汇总）
SELECT * FROM dim_store LIMIT 5;
SELECT * FROM ads_store_gmv_trend LIMIT 5;
-- 对比 ODS 与 DWD 字段差异，回答"DWD 洗掉了什么"：
SELECT * FROM ods_orders LIMIT 5;
SELECT * FROM dwd_trade_order_detail LIMIT 5;
```

记录单必答四题：①ods_orders 与 dwd_trade_order_detail 字段差在哪、少了约 4.9 万行可能是什么单（测试单/未支付/作废）；②dim_store 里"一行是什么"、有哪些口径属性（大区/城市/业态）；③dws_store_daily_sales 一行是什么、为什么 19 万行（门店数×天数去重）；④ads_store_gmv_trend 为谁而生、可直接配图吗。

#### 子步骤 2：五问推演＋NL 交叉验证（25′）

按三问法判层后，用 DAP-v2 控制台问同样的问题核对结果一致性：

| 业务问题 | 判层 | 用表 |
|---|---|---|
| 订单 202509001233 为什么退款 | DWD（单笔明细） | dwd_trade_order_detail |
| 华东区门店有哪些业态分布 | DIM | dim_store |
| 昨天各门店销售额 | DWS（门店×日已汇总） | dws_store_daily_sales |
| 上月集团 GMV 总量 | DWS 汇总/ADS | dws_store_daily_sales / ads_store_gmv_trend |
| 近 12 周 GMV 趋势（经营会图表） | ADS | ads_store_gmv_trend |

每题双轨取证：手写伪 SQL（判层依据）＋控制台 NL 提问（结果核对）；两者数字不一致即触发"口径仲裁"讨论。

Q4 判层后的伪 SQL 示例（在 DWS 汇总，不回明细层重算）：

```sql
SELECT SUM(daily_gmv) AS month_gmv
FROM dws_store_daily_sales
WHERE stat_date BETWEEN '2025-09-01' AND '2025-09-30';
-- 判层理由：要"汇总"且口径已冻结在 DWS；若在 ods_orders 现算，
-- 退款冲抵/测试单过滤/门店归属关联要整段重写一遍（口径漂移源头）
```

#### 子步骤 3：跨层取数反例解剖（15′）

现场写一条"在 ODS 直接算 GMV"的 SQL：需要自行处理退款冲抵、测试单过滤、门店归属关联——让学生数一数这条 SQL 埋了几个口径假设。质量治理角色牵头产出《三类风险清单》：口径漂移（下次别人再写一遍就不一样）、性能（105.9 万行每次现算，DWS/ADS 已预汇总）、复用性（逻辑锁死在某人的临时 SQL 里，无法治理）。

#### 子步骤 4：售后域分层规划（20′）

按《分层表设计模板》产出初稿（建议起点，鼓励修正）：ods_aftersale_refund（贴源）、dwd_aftersale_refund_detail（明细事实，行=一次退款）、dim_refund_reason（退款原因维度）、dws_store_aftersale_daily（门店×日售后汇总）、ads_store_refund_rate_trend（退款率趋势）。每表必填五栏：表名/粒度声明/主键/核心度量/来源映射（从哪张上游表的哪些字段来）。本产物即企业站 PR 的内容底稿。

售后域规划起点示例（各组可修正，修正须给理由）：

| 表 | 粒度 | 主键 | 核心度量 | 来源映射 |
|---|---|---|---|---|
| ods_aftersale_refund | 一次退款申请 | refund_id | 原始金额/状态 | 源系统退款单 |
| dwd_aftersale_refund_detail | 一次有效退款 | refund_id | 退款额/原因码 | ods_aftersale_refund 清洗＋dim 关联 |
| dim_refund_reason | 一个原因码 | reason_code | 原因名称/所属大类 | 客服口径表 |
| dws_store_aftersale_daily | 门店×日 | store_id＋stat_date | 退款单数/退款额 | dwd 汇总 |
| ads_store_refund_rate_trend | 门店×周 | store_id＋week | 退款率/环比 | dws 售后÷dws 销售 |

- 【教师活动】抽 2 组各 6 分钟讲堂："退款率 3.2%/2.1%/4.0% 三个数字怎么在分层里终结"；组织量表评分与教师点评（重点：是否用"粒度/来源映射"说话）。
- 【学生活动】讲堂展示＋互评；登记回炉点；领取企业站 PR 任务要求。

## 八、评价设计（任务单评分表）

| 评价维度 | 权重 | 评分标准 |
|---|---|---|
| 表解剖记录单 | 20 | 优：四道必答题全对＋字段差异具体到列；良：对 3 题；中：对 2 题；差：≤1 题 |
| 五问判层推演 | 20 | 优：5/5 正确且判层理由引用三问法；良：4/5；中：3/5；差：≤2/5 |
| 反例风险清单 | 15 | 优：三类风险各配 ODS 实例；良：三类齐无例；中：只有 2 类；差：≤1 类 |
| 售后域设计说明书 | 30 | 优：≥4 表五栏齐全＋来源映射闭环；良：五栏缺 ≤3 处；中：缺 4–6 处；差：结构不全 |
| 学生活动参与（角色履职） | 15 | 按三角色分工痕迹（记录单署名角色）与讲堂表现折算 |

**过程性观察点**：①子步骤 2 中发现"手写 SQL 与 NL 结果不一致"时是否主动追口径（而非改数字凑一致）；②子步骤 4 是否出现"跳过 DIM 直接把门店名冗余进 DWD"的争论（可观察维度建模理解深度）；③互审意见是否具体到字段级。
