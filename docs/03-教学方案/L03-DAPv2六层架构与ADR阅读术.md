# 学习情境 L03：DAP-v2 六层架构与 ADR 阅读术（6 学时）

## 一、学习情境基本信息

| 学习领域 | LF | 讲次 | 学时 | 布鲁姆主层级 | 双元场地 |
|---|---|---|---|---|---|
| LF1 数据中台认知与数仓架构规划 | LF1（第 3/3 讲） | L03 | 6（校内 4 ＋ 企业站 2） | 理解 / 分析（解/析），评价渗透 | 校内理实一体教室＋企业实训站（dap-v2 仓库与集群） |

- **企业站 PR 任务**：向课程仓库提交一张"架构说明补充/勘误 PR"——通读 `docs/design/architecture/` 架构文档与 `docs/design/adr/`（共 8 份，精读 6 份），为其中一处含糊/缺漏/笔误提交补充段落或勘误（含修订理由），由企业导师评审合并。
- **课后费曼任务**：学生讲堂①预演——每人自选 1 份 ADR，准备 3 分钟脱稿讲解（背景约束→决策→代价），下次课开讲前抽讲。

## 二、任务描述

某零售集团数据部收到集团架构办评审意见：DAP-v2 涉及 20+ 组件，"为什么不用现成编排框架？为什么元数据库还要读写分离？"要求项目组一周内提交架构说明与决策依据。数据部决定让新员工先精读 6 份 ADR，再向架构办复述六层架构与关键取舍，并接受现场质询。

## 三、学习目标

1. 【理解】能按数据流顺序讲清 DAP-v2 六层架构：①接入层 React 控制台→②网关层 GraphQL/REST（FastAPI+Strawberry）→③编排层 LangGraph 风格状态图→④Agent 层（洞察/质量/根因/ETL 四 Agent）→⑤知识引擎层（CRDB 元数据＋Milvus 混合 RAG＋Nebula 血缘）→⑥工具层 MCP（sql-executor 四层护栏），TiDB 零售数仓为数据底座；每层一句话职责＋一个真实组件名。
2. 【理解】能说出 ADR（Architecture Decision Record）的三段结构——背景 Context、决策 Decision、后果 Consequences（含被放弃的替代方案），并解释"替代方案对比"为什么不可省。
3. 【分析】能拆解 ADR-001～006 各自解决的约束与付出的代价：001 复用基建、002 自研编排、003 v2 并行灰度、004 诚实容量、005 三级缓存、006 Pulsar 异步＋DLQ。
4. 【分析·渗透】面对质询（如"FAQ 为什么不全走 LLM"），能从架构图定位相关层、引用真实指标（FAQ 直答 420ms vs LLM 56s；held-out 24 题 91.7%；k6 140RPS）组织证据作答。
5. 【评价·渗透】能按互评量表对同伴架构图给出 ≥3 条有依据的评价（至少 1 条改进建议），而非"画得好看"式空评。

## 四、教学重点与难点

### 教学重点

1. 六层架构的分层逻辑与每层核心组件：分层即"变化速率隔离"（前端月抛、编排周调、数据底座十年不动），接口在层间（GraphQL schema、MCP 工具协议）。
2. ADR 三段式阅读法与"取舍"意识：每个决策都是用一种代价换一种收益（自研编排＝掌控状态循环，代价是自己修 bug）。

### 教学难点（附突破策略）

1. **理解决策的"代价面"**——学生只看结论不看放弃的替代方案，把 ADR 读成"通知"。
   突破策略：①"买房 vs 租房"决策表类比（决策=选项+约束+代价，缺一不可）；②每人精读 1 份 ADR 后必须填写"放弃清单"表格（放弃了什么/为什么能承受/什么条件下反悔），组内互讲。
2. **从"看懂图"到"经受质询"**——被动复述容易，被追问即崩。
   突破策略：红蓝对抗——蓝方讲解员、白方持质询卡追问（质询卡预置 8 问，含冷门角度：Milvus 挂了 FAQ 还能答吗？编排层为什么不用 LangGraph 现成框架？），答不上记为"回炉点"而非扣分羞辱。

### 6.1 资讯（30′）

- 【教师活动】宣读架构办质询函原文（投影两个质询问题）；在大屏上以一次真实 NL 查数请求为线索走读六层：请求从 React 控制台发出→GraphQL 网关（FastAPI+Strawberry）→编排层状态图→路由到洞察 Agent→知识引擎先查（CRDB 元数据命中？Milvus 混合检索？）→未命中则经 MCP 调 sql-executor（四层护栏）→SQL 落 TiDB 数仓执行→结果回传渲染。同步对照 `kubectl get pods -n dap-v2 -o wide`，把每一层指到真实 Pod。
- 【学生活动】跟随走读填《架构走读笔记》：每层记"组件名/一句话职责/这次请求经过它时发生了什么"。
- 【教学方法】链路追踪法（一条请求串六层）＋现场对照（图↔Pod）。
- 【设计意图】用动态数据流代替静态框图背诵，先有"旅程感"再谈"分层论"。

**六层职责速查表（走读板书底稿，也是"挂了会怎样"抽测题源）**

| 层 | 核心组件 | 一句话职责 | 挂了会怎样 |
|---|---|---|---|
| 接入 | React 控制台 | 人机入口，收敛提问与展示 | 业务不可用，链路无损 |
| 网关 | FastAPI+Strawberry（GraphQL/REST） | 协议接入、鉴权、限流 | 全站入口不可达 |
| 编排 | LangGraph 风格状态图 | 决定"先查知识还是先生成" | 请求无路由，全面超时 |
| Agent | 洞察/质量/根因/ETL 四 Agent | 四类任务的领域智能 | 对应能力退化，其余可用 |
| 知识引擎 | CRDB 元数据＋Milvus 混合 RAG＋Nebula 血缘 | 口径/知识/血缘的复用中枢 | 直答失效、生成质量下滑 |
| 工具 | MCP sql-executor | 唯一 SQL 出口，四层护栏 | 所有查数不可用（安全优先） |

### 6.2 计划（30′）

- 【教师活动】布置 Jigsaw：每组 6 人各领 1 份 ADR；给出精读模板四栏（背景约束/决策/后果与代价/放弃清单）；引导预测架构办可能的 8 类质询并制成问题池。

ADR 阅读模板（每人一张，四栏必填，缺栏重读）：

| 栏目 | 要回答的问题 |

### 6.4 实施（90′）

#### 子步骤 1：六层走读深读（20′）

回到仓库，按层找到代码/配置落点并登记（示例）：

| 层 | 仓库落点（示例） | 学生需记录的证据 |
|---|---|---|
| 接入 | `web/`（React 控制台） | 提问输入框调用的 GraphQL mutation 名 |
| 网关 | `services/gateway/`（FastAPI+Strawberry） | /graphql 与 /rest 两个入口路由 |
| 编排 | `services/orchestrator/` 状态图定义 | 状态节点与转移条件各 3 个 |
| Agent | 洞察/质量/根因/ETL 四 Agent 目录 | 每个 Agent 一句话职责 |
| 知识引擎 | CRDB 元数据/Milvus 集合/Nebula 血缘 | FAQ 元数据表名、向量集合名 |
| 工具 | `services/sql-executor/` | 四层护栏的代码入口顺序 |

#### 子步骤 2：ADR 拼图精读（30′）

每人按四栏模板精读主责 ADR，重点填"放弃清单"。参考锚点（学生需在原文中验证而非照抄板书）：

- ADR-001 复用基建：约束是两人小团队+已有 K8S 集群；决策为最大化复用数据基建（TiDB/CRDB/Milvus/Pulsar）；代价是接受既有组件边界。
- ADR-002 自研编排：约束是 LangGraph 风格状态循环需深度掌控；决策为自研轻量编排而非直接引入重型框架；代价是自担维护、放弃框架社区生态。
- ADR-003 v2 并行：约束是 v1 在用不能停；决策为 v2 并行建设+灰度切流；代价是一段时间双轨运维成本。
- ADR-004 诚实容量：约束是单副本两节点集群压不出 100 万并发；决策为只声明实测容量（k6 140RPS 实测口径）+线性外推公式写明假设；代价是"数字不好看但可审计"。
- ADR-005 三级缓存 / ADR-006 Pulsar 异步＋DLQ：分别回答"为什么 FAQ 能 420ms"与"慢任务为什么不能堵死网关"。

组内轮讲（每人 3 分钟），听者签字确认并在对方"放弃清单"上补 1 个追问。互讲纪律：主讲人不许念原文段落，必须换成自己的话；追问未答上的条目当场记入"回炉点"清单，不许跳过。

#### 子步骤 3：默画架构图（20′）

全组合力在白板默画：六层＋TiDB 底座＋层间接口标注＋至少 3 个指标落位（如 420ms 标在网关/知识引擎之间、140RPS 标在网关、91.7% 标在 NL2SQL 管线、四层护栏标在工具层）。不允许照抄原图——凭走读记忆重构。

#### 子步骤 4：红蓝对抗（20′）

组间对抗：甲组 2 人任蓝方讲解员，乙组抽 3 张质询卡追问（例：①为什么元数据选 CRDB 还做读写分离？②Milvus 不可用时查询链路怎么走？③held-out 24 题为什么必须与训练/调优集隔离？④140RPS 之后系统会先死在哪一层？）。答不全记"回炉点"，轮换。教师只在僵局时给线索。

质询卡（8 问，红蓝对抗与教师抽测共用）：

1. 为什么不直接用现成编排框架，而要自研状态图？
2. 元数据为什么选 CRDB，还额外做读写分离？
3. Milvus 不可用时，查询链路降级后怎么走？
4. FAQ 为什么不全走 LLM 生成？
5. held-out 24 题为什么必须与调优用例隔离存放？
6. 140RPS 再往上压，最先饱和的会是哪一层？
7. "语法正确但越权"的 SQL 会被四层护栏的第几层拦下？
8. v1 还在服役，v2 切流凭什么保证可回退？

### 6.5 检查（40′）

- 【教师活动】发放架构图核对单（六层齐全/组件名准确/数据流向正确/≥3 指标落位/层间接口标注），组织组间互评并抽样复述。
- 【学生活动】按互评量表给邻组打分并写 1 条改进建议；接受教师抽测（随机指图中一层问"它挂了会怎样"）。
- 【教学方法】核对单互评＋故障假设抽测。
- 【设计意图】"挂了会怎样"是检验架构理解的最廉价探针——能答说明真懂职责与依赖。

**架构图核对单（互评依据，5 项全过为优）**

| # | 核对项 | 判定 |
|---|---|---|
| 1 | 六层＋TiDB 底座齐全、层序正确 | |

| 3 | 数据流向与真实请求旅程一致 | |
| 4 | ≥3 个指标落位到正确的层 | |
| 5 | 层间接口（GraphQL schema／MCP 协议）有标注 | |

### 6.6 评价＋学生讲堂（30′）

- 【教师活动】主持"向架构办汇报 3 分钟"（每组 1 人，面向全班扮演的"架构办"，必须回应质询函两个原始问题）；量表评分并点评"证据引用"质量。
- 【学生活动】汇报答辩；完成自评互评；登记回炉点，领取企业站 PR 任务与费曼任务（预演 3 分钟讲 ADR）。
- 【教学方法】角色扮演＋表现性评价。
- 【设计意图】闭环本讲情境任务（回应架构办），并为下讲学生讲堂①做好预演。

**教师收束两句话**：①架构图不是画给评委看的，是画给三年后接手的人看的；②ADR 的价值一半在"决策"，另一半在"记录了为什么没选另一条路"。

## 八、评价设计（任务单评分表）

| 评价维度 | 权重 | 评分标准 |
|---|---|---|
| 架构走读笔记 | 15 | 优：六层各有组件名＋职责＋旅程事件；良：缺 1 层细节；中：仅组件名；差：层序错乱 |
| ADR 放弃清单（6 份） | 25 | 优：每份含被弃方案+可承受理由+反悔条件；良：缺反悔条件；中：仅结论复述；差：未填 |
| 默画架构图 | 25 | 优：核对单 5 项全过；良：过 4 项；中：过 3 项；差：≤2 项 |
| 红蓝对抗表现 | 15 | 优：答对≥2 题且能定位层；良：答对 1 题有定位；中：答对但说不出层；差：未参与 |
| 汇报与证据引用 | 20 | 优：回应两个原始质询＋引用≥3 个真实指标；良：回应 1 个；中：泛泛而谈；差：未汇报 |

**过程性观察点**：①精读时是否在 ADR 原文标注而非抄板书锚点（防"锚点即答案"的假验证）；②红蓝对抗中"回炉点"是否被如实登记（HSA 观察）；③互评建议是否指向结构（层/接口/指标）而非字迹美观。
