## 〇、本讲术语小白卡（先看懂再开工）

| 术语 | 人话解释 | 生活化类比 |
|---|---|---|
| p95 | 100 个请求里第 95 名的成绩——比平均分诚实，平均分会被极端值拉偏 | 全班成绩看第 95 名，不看被学霸拉高的平均分 |
| 均值陷阱 | 9 人 1 秒＋1 人 100 秒，平均 10.9 秒——其实 9 人都很快 | 9 个人排队 1 分钟、1 个人排队 100 分钟，"平均等待 10.9 分钟"骗了谁 |
| 覆盖率 | 代码里被测试"踩过"的行数占比 | 体检套餐检查过的项目占总项目的比例 |
| held-out | 考试卷：平时练习绝不让见过的题，防"背题" | 期末题绝不从平时作业里原样抽 |
| bootstrap 置信区间 | 把成绩单反复重新抽样算分，看分数在什么范围里晃——区间宽说明样本少、底气虚 | 只测 3 次体温不敢报数，测 30 次才敢说"大概 37 度左右" |
| 拐点 | 再加人就加不动的那道坎：RPS 不再随并发增长 | 食堂窗口加到第 4 个后队伍不再变短——厨房产能到顶了 |
| 测试金字塔 | 底层单测多而快、顶层压测少而贵的分层测试结构 | 体检套餐：血常规便宜常查，CT 贵少查，负荷试验最贵只做一次 |

## 三、学习目标

1. 【理解】画出本项目测试金字塔（单元 67 → 契约/护栏 → E2E 7 → 压测/评测）并说明各层职责、数量配比与执行成本的反比关系。
2. 【应用】运行 pytest＋覆盖率门禁与 Playwright 无头 E2E，从报告定位失败用例所属层与修复责任。
3. 【分析】判读 k6 阶梯压测报告：p95 延迟、错误率 2.4% 的构成、RPS 拐点档位，并写出一句瓶颈结论。
4. 【评价】用统计视角评判评测证据：论证"12 题 100% 为何没有统计意义"，说明 24 题＋held-out 12＋bootstrap 95% CI 的必要性。
5. 【评价】论证覆盖率门禁为何设 80%（项目实测 87%）：过高（凑数测试）与过低（回归裸奔）的代价权衡。

## 四、教学重点与难点

**本讲主链路（板书/PPT 用）：测试金字塔＝发布证据链**

```flow
代码改动 → ①单测67条(秒级) → ②护栏/契约测试 → ③E2E 7条(分钟级) → ④k6压测+评测集 → 门禁证据链
```

```flow
证据三问：①p95多少 → ②错误率是谁的错 → ③拐点在第几档 → 一句话瓶颈结论
```

### 教学重点
1. 测试金字塔的成本—反馈结构：底层数量多跑得快（毫秒级）、顶层数量少贴近真实（分钟级），66+→7→1 的配比不是随意的。课堂类比（正文版，讲堂再让学生自创）：体检套餐——血常规（单测，便宜量大）→ CT（E2E，贵但全面）→ 运动负荷试验（压测，最贵只做一次）。
2. k6 报告三要素判读法：p95（尾延迟比均值诚实——"9 个人 1 秒＋1 个人 100 秒，平均 10.9 秒"的均值陷阱例子现在就讲，不等课后）、错误率（2.4% 是谁的错——超时还是断言）、拐点（RPS 不再随 VU 增长的台阶）。

### 教学难点
1. **"12 题 100% 为何无统计意义"的统计直觉**——学生直觉是"全对还不说明问题？"
   - 突破策略（三步台阶）：台阶 1·生活类比——掷硬币连续 12 次正面，你敢说硬币是"百分百正面"吗？"全对"可能只是运气；台阶 2·看一次现场演算——真实准确率 0.85 时 12/12 的概率约 14%（0.85¹²），0.70 时仍有约 1.4%（幂次＝概率连乘），再演示 bootstrap 重采样让置信区间"长出来"；台阶 3·动手复现——学生自己跑 bootstrap 脚本改重采样次数，观察区间宽窄变化，直觉冲突被数据化解（教授方法学的通俗版）。
2. **覆盖率门禁的度**——为什么是 80 不是 100 也不是 50。
   - 突破策略（三步台阶）：台阶 1·生活类比——门禁设 100% 等于要求"体检全项目零免检"，逼着人造假报告；设 50% 等于"一半器官不查"；台阶 2·看一次真实报告——读仓库覆盖率报告里 `Missing` 列最长连续行段，区分"没测到的逻辑"与"测了但断言空洞"（后者更危险）；台阶 3·动手复现——两个反例对照：100% 门禁催生"为覆盖而测"（断言空洞），50% 门禁下 L14 那类护栏函数可能整段裸奔；用"护栏模块必须 80+、胶水代码可豁免"的分级门禁收束讨论。

## 六、教学过程设计

### 第 1 步：资讯（30 分钟）

**【教师活动】** 白板画塔：单元 67（含 test_bindings 占位符绑定防线）→ 契约/护栏（L14 恶意单测归宿）→ E2E 7 条（Playwright 无头全链路）→ 压测与评测（k6 阶梯、24 题评测）；给出实测数字 67/7/300VU/2.4%，提问"如果只能保留一层，丢哪层最疼？"。
**【学生活动】** 对照dap-v2 的 tests/ 目录数一数各层文件数与金字塔是否吻合；把本学期自己提交过的 PR 归类到塔的某一层并贴名签。
**【教学方法】** 图示讲解＋目录考古。
**【设计意图】** 用学生自己的提交史锚定金字塔——"我的改动在哪一层被保护"比抽象分层更有代入感；丢层思想实验为后面门禁讨论埋线。

### 第 2 步：计划（30 分钟）

**【教师活动】** 发布"证据链任务单"：四站（单测覆盖率站/E2E 站/k6 判读站/评测统计站）各须产出一条可核验结论；给出 k6 判读三问模板与统计站实验步骤。
**【学生活动】** 排定小组四站的顺序与分工（建议底→顶顺序）；预填 k6 三问（p95 是多少/错误率构成/拐点在第几档 VU）的"预判值"；圈出自己本学期改动对应的单测缺口（为企业站 PR 备料）。
**【教学方法】** 站点式学习计划＋预测—验证。
**【设计意图】** 预填预判值延续 L14 的认知冲突法；提前圈单测缺口让企业站 PR 有明确靶子，避免"随便补两个测"。

### 第 3 步：决策（20 分钟）

**【教师活动】** 逐组确认：补测对象选哪个函数（优先护栏/绑定/缓存等共享模块，符合 TCG"共享包必测"）、预计覆盖增量；裁决争议（如"我的改动是 yaml，测什么？"→引导为"部署变更的冒烟脚本断言"）。
**【学生活动】** 定稿补测清单（2 个单测的目标函数与断言草案）；在任务单登记选择理由。
**【教学方法】** 决策谈话。
**【设计意图】** "yaml 改动测什么"是真实工程问题，公开裁决一次，全班受益；补测对象决策本身就是评价层级行为（判断什么值得测）。

### 第 4 步：实施（90 分钟）

#### 4.1 金字塔底座：单测＋覆盖率门禁（约 20 分钟）

这步在干什么：用仓库真实入口跑全部单测并统计 dap_core 覆盖率，低于 80% 直接判红（门禁，不是建议）：

```bash
# dap-v2 真实命令（Makefile test 目标，等同）：必须从 packages/dap_core 目录起跑，
# 直接在仓库根跑 pytest 会因 rootdir 解析错位收集 0 条测试（exit 5，已踩过的坑）
cd packages/dap_core
uv run pytest ../../services ../../packages -q -p no:cacheprovider \
  --cov=dap_core --cov-report=term-missing --cov-fail-under=80
# 怎么判断对了：67 测全绿（当前基线，随 main 演进以 make test 实时输出为准）、行覆盖 87%、passed 且无 failed

uv run pytest tests/test_bindings.py -q -p no:cacheprovider   # 占位符绑定防线：参数必须走绑定而非拼接
```

读报告两个动作：① 找出 `Missing` 列里最长的连续行段（最值得补的缺口）；② 区分"没测到的逻辑"与"测了但断言空洞"（后者更危险）。

#### 4.2 中层：E2E 7 条与冒烟 9 项（约 15 分钟）

```bash
make e2e      # 等同 cd tests/e2e && npx playwright test：7 条无头全链路（登录→提问→出数→图表）
make smoke    # 等同 bash tests/smoke.sh：9 项冒烟（登录/护栏/GraphQL/SSE 流/质量规则/审批/控制台…）
```

判读：E2E 失败先问"哪一层背锅"——E2E 红而单测绿＝集成缝隙（环境/契约），两层都红＝逻辑缺陷；记录一条失败归因（若全绿，回放教师预置的失败视频）。

#### 4.3 顶层之一：k6 阶梯压测报告判读（约 25 分钟）

```bash
# 仓库真实脚本与报告路径：tests/load/k6_gateway.js → tests/load/k6_summary.json
k6 run tests/load/k6_gateway.js --summary-export=tests/load/k6_summary.json
# 上一次全量实测口径：300VU 阶梯、26865 请求、稳态 ~140RPS、p95 3.3s、错误率 2.4%
# 口径注记（工程诚实）：140RPS 为 70% 缓存混合负载下的稳态实测，并非"新问句全链路拐点"；
# "拐点在哪"由学生用本档阶梯数据自行判读，不预设标准答案
```

三问判读（任务单必填）：
1. **p95 是多少？** 尾延迟代表最差的 5% 用户体验，比均值诚实；对照 SLA（如 p95<800ms）。
2. **错误率 2.4% 是谁的错？** 拆解构成：超时（资源层 L2 的 20s 掐断/连接池排队）还是断言失败；2.4%≠灾难，但要能说清来源。
3. **拐点在第几档 VU？** RPS 不再随 VU 增长、p95 陡增的台阶即容量拐点；判读以本档实测曲线为准（历史实测稳态 ~140RPS 可作参照，但它是 70% 缓存混合负载口径，不是新问句全链路的标准答案——呼应 L6 容量外推公式的诚实口径）。

产出：在报告 JSON 上圈出拐点档位，写一句瓶颈结论（如"缓存命中率下降后 DB 直查比例上升，p95 陡增"）。

#### 4.4 顶层之二：评测集方法学＋混沌回放（约 30 分钟）

（a）"12 题 100%"的统计脆弱性（教授方法学的通俗版）：

```python
# 若真实准确率 p=0.85，12 题全对的概率：
0.85 ** 12   # ≈ 0.142 —— 真实水平 85% 的系统有 14% 概率"看起来全对"
0.70 ** 12   # ≈ 0.014 —— 连 70% 的系统也可能偶发 12/12
# 结论：12/12 区分不了 0.70 与 0.85，"100%"不是证据
```

升级方案三件套：**24 题**（样本翻倍）＋**held-out 12**（评测题绝不进 few_shots/知识库，防背题）＋**bootstrap 95% CI**：

```bash
# 评测脚本真实路径：dap-v2 tests/eval/run_eval.py（24 题评测集内嵌，产出 eval_report.json）
# bootstrap 重采样由教师发放的脚本完成（对 eval_report.json 的对错序列重采样 10000 次）
uv run --project packages/dap_core python tests/eval/run_eval.py
# 输出（示例口径）：acc=0.875，bootstrap 95% CI [0.71, 0.96]
# 报告口径：必须带区间，"87.5%"单独出现即不诚实
```

（b）混沌降级回放（Redis 故障注入时间线）：

```
T+0    注入：课程环境断开 dap-cache 连接（故障注入脚本）
T+2s   主链直穿：/api/nl2sql 仍返回 200，响应头 degraded:true、cache_hit:false
T+8s   p95 短暂抬升（全部流量落到 DB）——对照 4.3 的拐点解释
T+90s  Redis 恢复 → 缓存命中回升、degraded 消失（自愈回归）
```

契约要求（DPC 铁律）：**每条降级路径必须有测试证明它会被触发且行为正确**——混沌回放就是那条测试的现场版；"降级没崩"和"降级被测过"是两回事。

### 第 5 步：检查（40 分钟）

**【教师活动】** 组织"证据链互审"：相邻组交换四站结论，逐条核对是否"可核验"（有命令、有数字、有出处）；抽查 2 组重跑对方的 k6 判读与 bootstrap 数字。
**【学生活动】** 互审打勾/打叉：p95 有没有写具体毫秒？错误率有没有拆构成？拐点有没有指认档位？评测结论有没有带置信区间？覆盖率结论有没有区分"没测"与"空测"？修补被打叉项。
**【教学方法】** 同伴互审＋证据核查。
**【设计意图】** "可核验"是 L16 发布决策的前置训练——不可核验的结论在门禁评审会上等于没有；互审清单直接复用 HSA（诚实自评）文化的操作化标准。

### 第 6 步：评价＋学生讲堂（30 分钟）

**【教师活动】** 主持学生讲堂⑥：抽 2 组各 5 分钟讲一份 k6 报告（三要素齐全为及格线）；10 分钟总结证据链全景并抛出 L16 引子——"证据齐了，谁有权按下上线按钮？"；布置费曼任务与岗位视角（测试开发工程师的一天）。
**【学生活动】** 讲堂主讲＋同伴按"三要素/一句话结论/诚实度"互评；每人写一句"我今天修正的一个直觉"（如"全对≠正确""均值会骗人"）投入反馈箱。
**【教学方法】** 费曼讲堂＋概念变更自述。
**【设计意图】** 统计直觉的修正是本讲最难的认知成果，用"修正了什么直觉"显性化；讲堂与 L16 答辩的"讲证据"能力同构，提前彩排。

## 九、课后费曼任务

- **讲给谁**：同学或家人（扮演"不懂技术的运营总监"最佳）。
- **讲什么**：讲一份 k6 报告——① p95 是什么、为什么比平均值更该看（举"9 个人 1 秒+1 个人 100 秒"的例子）；② 错误率 2.4% 意味着什么、要怎么追问构成；③ 拐点为什么是"诚实容量"（连回 L6 的外推公式）。
- **自评三问**：① 对方听完后能复述"为什么平均值会骗人"吗？② 我有没有只报好数字、回避错误率构成？③ 如果对方追问"那 2.4% 能上线吗"，我能回答"要看构成与 SLA"而不是拍脑袋吗？
